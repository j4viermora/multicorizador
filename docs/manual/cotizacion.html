Flujo de cotización

Desde que alguien ingresa origen, destino y fechas hasta que aparecen precios comparables de cada aseguradora.

Motor único de cotización

Producer y landing pública usan el mismo pipeline async.

Tanto /producer/quotes como /cotizar/:slug persisten un Quote y encolan QuoteJob. No hay un segundo camino síncrono.
sequenceDiagram autonumber actor U as Usuario participant C as Controller participant DB as Quote participant QJ as QuoteJob participant PQ as ProviderQuoteJob ×N participant API as Aliados participant TS as Turbo Stream U->>C: Envía búsqueda C->>DB: Quote status=draft C->>QJ: perform_later(quote_id) C-->>U: Redirect / resultados (token) QJ->>DB: status=quoting loop Por cada Provider.active QJ->>PQ: perform_later PQ->>API: client.quote(quote) API-->>PQ: hash normalizado (1 o N planes) PQ->>DB: QuoteResult(s) success/error PQ->>TS: broadcast resultados end PQ->>DB: status=quoted (si hay éxitos)

Estado Significado ¿Editable?
draftArmando la cotización✅
client_pendingEsperando datos del cliente vía link✅
quotingConsultando APIs en paralelo❌
quotedHay al menos un precio exitoso✅
no_resultsNingún proveedor respondió bien✅

cancelledDescartada por el productor❌
Regla: quoted solo se alcanza si existe al menos un QuoteResult con status: success. Si todos los proveedores fallan → no_results.

Jobs en background

QuoteJob

  • Input: quote_id
  • Hace: pasa Quote a quoting, encola un ProviderQuoteJob por cada Provider.active
  • Edge case: sin proveedores activos → no_results inmediato

ProviderQuoteJob

  • Input: quote_id, provider_id
  • Hace: llama InsuranceProviders.for(provider).quote(quote)
  • Retry: 3× con 5s backoff en ProviderError
  • UI: re-renderiza comparador vía Turbo Stream en cada respuesta

Escenario A — Productor completa todo

El agente tiene los datos del viajero y dispara la cotización desde su panel.

flowchart TD A[Productor crea/selecciona Traveler] --> B[Completa Quote en /producer/quotes/new] B --> C[QuoteJob → ProviderQuoteJob ×N] C --> D[Comparador en /producer/quotes/:id] D --> E{¿Compra?} E -->|Hoy| F[Botón Seleccionar deshabilitado] E -->|Diseño| G[purchase_url → pasarela aliado]
  1. Productor autenticado en /producer
  2. Crea Traveler (cliente) si no existe
  3. Arma Quote con origen, destino, fechas, cantidad de viajeros
  4. Al guardar/enviar → QuoteJob.perform_later
  5. Ve resultados en tiempo real (Turbo Streams)
  6. Selecciona plan → (pendiente de implementar) redirect al checkout del aliado

Escenario B — Cliente completa vía link

El productor comparte un link; el cliente carga sus datos personales.

sequenceDiagram actor PR as Productor actor CL as Cliente participant L as Link participant Q as Quote participant J as QuoteJob PR->>Q: Quote con datos mínimos del viaje PR->>L: create_share_link! (7 días) PR->>CL: Envía URL /public/quotes/:token CL->>L: GET show (registra acceso) CL->>Q: PATCH con traveler + datos Q->>J: perform_later Note over CL: Mismo flujo async que Escenario A

Sistema de Links

  • Token: SecureRandom.urlsafe_base64(24)
  • Expiración: 7 días por defecto
  • Estados: active, expired, revoked
  • Trackeo: access_count, last_accessed_at

Escenario C — Landing pública (venta directa)

Visitante anónimo en /cotizar/ruka o /.

flowchart TD V[Visitante en /cotizar/ruka] --> F[Formulario de búsqueda] F --> Q[Quote creado created_by=client] Q --> J[QuoteJob] J --> R[/cotizar/ruka/resultados/:token] R --> W[Espera vía Turbo Stream] W --> CMP[Comparador por proveedor] CMP --> BUY[Seleccionar plan → comprar → checkout]
La landing usa el mismo QuoteJob que el productor. La UX muestra un spinner mientras status = quoting y se actualiza sola cuando llegan resultados — no hace falta recargar la página.

Comparador de resultados

Cómo se presentan los QuoteResult exitosos.

Layout: una fila por proveedor

Cada proveedor puede devolver varios niveles de plan (Básico, Estándar, Premium). Se agrupan en una fila horizontal; las filas se ordenan por la opción más barata de cada proveedor.

  • Método: Quote#offers_by_provider
  • Errores: Quote#failed_providers — se muestran aparte, no bloquean al resto
  • Proveedores fake: AssistCard, UniversalAssistance, TravelAce (4 tiers cada uno)
  • Real: Omint (cotización B2B, múltiples productos por llamada)
